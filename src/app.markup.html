◫ OrgLite — prototype

One HTML file that is the whole app: org-flavored plain-text notes with org-roam-style nodes & backlinks, zero Emacs, instant even at 100k+ lines — and, TiddlyWiki-style, the app and all your notes live inside the file itself.

Editing — one rendered buffer, Emacs/org style

  • The whole main area is one buffer: fully rendered (org-modern-style bullets, TODO pills, ☐/☑ checkboxes, timestamps, tags) and the editor — no source/view toggle.
  • Modal keys: j/k down/up · h/l left/right · i insert at cursor · a append · A end of line · o/O new line below/above · Esc back to normal.
  • In insert mode: Enter keeps the same level & item (splits at the cursor; on a heading the rest becomes a same-level heading, at the end of a heading it indents a body line under it; on a list item it continues the list) · Shift+Enter places the same item one indent deeper · Ctrl+Enter inserts a heading one level deeper than the current one · Ctrl+Shift+Enter inserts a heading at the level of the most previous heading · Tab inserts indentation · Ctrl+>/Ctrl+< indent/dedent the current line (CAPS-as-Ctrl friendly) · Backspace at line start joins lines · arrows move across lines. Typing edits the raw org text, and the pretty view re-renders live as you type — close a *bold* and it turns bold, type a heading and its TODO pill and tags appear immediately. Headings can nest to any depth — ****** … works, there is no three-level limit
  • Tab cycles fold (open → children → folded) · S-Tab fold all · t cycle TODO state · space toggle checkbox · x delete char · u undo.
  • Plain lists render org-modern style too: - and + become • bullets, 1. numbered items get accent-colored numbers — raw text underneath stays untouched
  • Ctrl+>/Ctrl+< in normal mode demote/promote the whole subtree under the cursor (org-metaright / org-metaleft) · 0 ^ $ line edges · gg/G top/bottom · Ctrl-f/b pages · / search buffer · n/N next/prev match · R refile subtree · z toggle preview pane

Saving (TiddlyWiki-style)

  • 💾 Save / Ctrl+S — writes everything into the HTML file. Chrome/Edge: pick the file once, then saves go in place. Firefox/Safari: an updated copy downloads — replace your old file with it.
  • Crash recovery — while you work, unsaved changes are mirrored to browser storage and restored automatically if you reopen without saving.
  • Portability — Load .org / Save .org export individual notes as plain text, so no file is ever hostage to this app.

Try it

  • Fold / unfold — put the cursor on a heading and press Tab to cycle open → children-only → folded (works even on the 100k-line stress file — rendering is virtualized).
  • Refile a subtree — R (or ⤵ Refile). Move a whole subtree to another file or heading. The :ID: travels with it, so backlinks keep working.
  • Preview pane — shows the whole subtree under the cursor, narrowed like org: every subheading with the text under it, refreshing as the cursor moves (click a subheading to jump; click a checkbox to toggle). Drag the divider to resize it, or z to hide it.
  • Backlinks — the tab shows linked references ([[id:…]]) and unlinked mentions of the selected heading.
  • Graph — nodes & edges derived from the link index
  • Themes — instant, CSS-variable-driven. UTF-8 headings/tags just work.
  • ⚡ Stress 100k — generates a 100,000-line file and shows the parse time.

How the single file works

  • Everything — markup, CSS, app code and your notes — is stored as JSON in a hidden <script> "store" inside the file, and a tiny boot script renders it (the same architecture as TiddlyWiki).
  • All <, > and & in the store are escaped, so the file survives any HTML round-trip without corruption.
  • A Tauri 2 shell (Rust, ~10 MB binary) can host this same file later for a windowed app that saves in place on disk — same file, no changes.

Notes: in the sandboxed preview, save/download/clipboard may be blocked — open the HTML file directly in your browser for full behavior.
